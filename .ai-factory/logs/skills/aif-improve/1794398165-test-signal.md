# Task 28: сигнал relay AC-5.11 взводится после add, без SQL очистки

**Date:** 2026-11-11 11:56
**Plan:** .ai-factory/plans/feature-e5-messaging
**Severity:** medium

## Problem

Сигнал onQuery по 'for update skip locked' мог прийти от пустого опроса relay (1000 мс) или от DELETE очистки до вставки строки; app.close() начинался до захвата строки, и проверки attempts=0/published_at null проходили впустую; signal/firstClaim не были объявлены

## Root Cause

Прошлая итерация добавила случай без учёта фоновых запросов того же пула (опрос relay, MessagingCleanup) с тем же фрагментом SQL

## Solution

Объявлены armed/signal/firstClaim; сигнал взводится после await add, фильтр исключает delete; добавлена проверка, что захват был

## Prevention

Сигналы onQuery по фрагменту SQL сверять со всеми фоновыми запросами стенда на том же пуле и взводить после шага, который делает событие возможным
