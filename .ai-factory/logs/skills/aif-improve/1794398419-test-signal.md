# Task 28: сигнал relay-кейса AC-5.11 — ждать начатой публикации

**Date:** 2026-11-11 12:00
**Plan:** .ai-factory/plans/feature-e5-messaging/
**Severity:** medium

## Problem

onQuery срабатывает до отправки claimBatch; app.close() сразу после сигнала мог выставить running=false до ответа захвата, пачка выходила по if (!running) break без публикации — гонка STOPPED неподтверждённой публикации не проверялась

## Root Cause

Прошлая правка сигнала устранила ранний сигнал до строки, но не учла, что onQuery срабатывает до DB round-trip и что drain проверяет running перед публикацией

## Solution

Перед app.close() добавлен waitFor по pg_stat_activity (соединение relay idle in transaction, последний запрос — захват без delete); пояснение Почему так дополнено, оговорён запрет на admin select for update как сигнал

## Prevention

Сигнал теста гонки должен фиксировать состояние, ради которого тест написан (публикация в полёте), а не только момент отправки запроса; сверять с порядком проверок в коде цикла
