# Поля аугментации ProvidedContext без readonly

**Date:** 2026-11-09 23:30
**Files:** src/testing/start-test-stack.ts
**Severity:** low

## Problem

`/aif-verify --strict` этапа E1 нашёл блокер `verify-rules-readonly-provided-context`: у шести полей `ProvidedContext` (`kitPostgresUrl` … `kitS3SecretKey`) в `declare module 'vitest'` не было `readonly`. Это нарушает `rules/base.md`: «`readonly` — у полей публичных интерфейсов».

## Root Cause

Поля перенесены дословно из плана (phase-03, задача 16) и из эталона O `global-setup.ts`. Там аугментация `ProvidedContext` написана без `readonly`. Правило про `readonly` применялось к собственным интерфейсам пакета (`TestStackOptions`, `RepoConventionsOptions`, `ComposeService`), а интерфейс, дописываемый в чужой модуль (`vitest`), сочли «чужим» и не проверили. Lint это правило не проверяет: `jsdoc/require-jsdoc` смотрит только TSDoc.

## Solution

Ко всем шести полям добавлен `readonly`. `project.provide(key, value)` и `inject(key)` продолжают работать: `readonly` ограничивает только запись в объект контекста, а не ключи. Сплошная проверка полей интерфейсов `src/**` других нарушений не нашла. Проверки: lint, typecheck, test (110), pack:check (24) — зелёные.

## Prevention

- Аугментация чужого интерфейса (`declare module '…' { interface … }`) в `src/**` — тоже публичная поверхность пакета: у её полей `readonly`, как у своих.
- В ревью этапа: поиск полей интерфейсов без `readonly` по `src/**` (awk по телам `interface`), пока правило не исполняет lint.
- Кандидат в lint: правило, требующее `readonly` у членов интерфейсов в `src/**` (например, `no-restricted-syntax` на `TSPropertySignature[readonly!=true]` внутри `TSInterfaceBody`).
