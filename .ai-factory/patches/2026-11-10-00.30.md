# instrument-import не видел dev-команду сервисов; разбор shell — через shell-quote, стадии Dockerfile, снимки сервисов

**Date:** 2026-11-10 00:30
**Files:** src/testing/repo-files.ts, src/testing/repo-conventions.ts, package.json, pnpm-lock.yaml, eslint.config.js, test/unit/testing/ac-1-8-repo-conventions.spec.ts, test/unit/testing/repo-files.spec.ts, test/unit/testing/ac-1-8-service-snapshots.spec.ts, test/unit/package/package-manifest.spec.ts, test/package/ac-1-1-package.spec.ts, test/fixtures/services/**, README.md
**Severity:** high

## Problem

Ревью E1 (`review-instrument-import-subshell`, AC-1.8, §3.8). Правило `instrument-import` пропускало без `--import …instrument` dev-команду всех четырёх сервисов: `CMD ["sh", "-c", "pnpm build && (… & exec node --watch … dist/main.js)"]`. Собственный токенизатор делил команды только по `&&`, `||` и `;`, поэтому скобки и `&` прилипали к словам, и файл входа получался `dist/main.js)`.

Снимки реальных репозиториев показали ещё три дефекта:
- `yaml` отказывал на `verdeect-orchestrator/compose.e2e.yml` («Excessive alias count»), и проверка репозитория падала целиком;
- переопределение без `command:` не наследовало команду базового `compose.yml`, и `*-migrate` в `compose.production.yml` оценивались не по своей команде;
- «подделкой» считался любой `node` с файлом входа не `main.*`, хотя по §3.8 подделка — это `*.main.ts`. Из-за этого CLI-задания с ключами `envBase` выпадали из `stop-grace-period`.

## Root Cause

Разбор shell был написан вручную и покрывал только формы из эталонной фикстуры. Фикстура была синтетической и не повторяла реальные команды сервисов. Правила проверялись на файлах по отдельности, без семантики слияния Compose и без стадий Dockerfile. Определение «подделки» было расширено против текста PRD.

## Solution

- Разбор shell перенесён на `shell-quote` 1.12.0 (CJS, именованный импорт из ESM работает; в `dependencies`, импорт только из `/testing`). Операторы `&&`, `||`, `;`, `&`, `|`, `(`, `)` делят команды. `$` на время разбора заменяется символом U+E000, поэтому `$VAR` и `${VAR}` не подставляются пустой строкой. Номер дескриптора перед перенаправлением (`2>&1`) и цель перенаправления в аргументы не попадают.
- Dockerfile разбирается по стадиям `FROM`: действуют последние `CMD` и `ENTRYPOINT` стадии. Exec-форма `ENTRYPOINT` без файла входа склеивается с exec-формой `CMD` той же стадии; разные стадии не склеиваются.
- `yaml`: `maxAliasCount: 10_000` (собственные файлы репозитория).
- Приложения: команда переопределения наследуется из `compose.yml`; подделка — ровно `*.main.ts` / `*.main.js`.
- Снимки `test/fixtures/services/{bff,identity,orchestrator,platform}` (`git show HEAD:…`, коммиты в `SOURCE`) и тест полного списка нарушений; каждое нарушение сверено с файлом.
- `shell-quote` запрещён в `src/config` и `src/internal` через lint; `pack:check` проверяет, что `dist` рабочих подпутей его не импортирует.

## Prevention

- Правила проверки чужих репозиториев прогонять на снимках реальных файлов, а не только на синтетической фикстуре: синтетика повторяет предположения автора.
- Для языков с грамматикой (shell, YAML, Dockerfile) — парсер, а не регулярные выражения и ручные токенизаторы.
- Правила по нескольким файлам учитывают семантику слияния инструмента: Compose (переопределения), Docker (стадии, `ENTRYPOINT` + `CMD`).
- Определения из PRD переносить дословно, без расширения («подделка вида `*.main.ts`»).
