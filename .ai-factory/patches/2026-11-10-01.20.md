# assertRepoConventions: многострочные скрипты, опции оболочки, ENTRYPOINT + shell CMD, слитый сервис Compose

**Date:** 2026-11-10 01:20
**Files:** src/testing/repo-files.ts, src/testing/repo-conventions.ts, test/unit/testing/ac-1-8-repo-conventions.spec.ts, test/unit/testing/repo-files.spec.ts, README.md
**Severity:** high

## Problem

Review 3 E1 (KT-06, AC-1.8). Правило пропускало нарушения на реалистичных формах файлов сервисов — каждый случай воспроизведён до правки:
- многострочный `sh -c` (`migrate\nexec node dist/main.js`) и `#`-комментарий: `shell-quote` не делит по переводу строки, а комментарий съедает весь остаток скрипта;
- `sh -ec`, `bash -lc`, `sh -e -c`, `bash -o pipefail -c` — скрипт не раскрывался;
- `ENTRYPOINT ["/sbin/tini","--"]` + shell-форма `CMD` — `CMD` терялся;
- переопределение с одним `stop_grace_period: 5s` не считалось приложением: ключи `envBase` были только в базе;
- база захардкожена как `compose.yml`;
- невалидный JSON в `CMD` обрывал всю проверку файла;
- `${STOP_GRACE:-15s}` давал ложное «не распознан»;
- `SHUTDOWN_TIMEOUT_MS=20000 # ms` читался как умолчание 10000, а неразбираемое значение молча заменялось умолчанием;
- в CI не снимался префикс `docker.io/library/`;
- неполный список опций `node` со значением (`--watch-path src` принимался за файл входа).

## Root Cause

Разбор строился от форм, встреченных в эталонной фикстуре и первых снимках, а не от грамматики инструментов: shell (строки, комментарии, опции), Docker (`ENTRYPOINT` + `CMD`, shell-форма), Compose (слияние с базой, порядок поиска файла, комментарии в `env_file`), node (опции со значением). Наследование от базы было сделано частично: для `command:`, `stop_grace_period` и `SHUTDOWN_TIMEOUT_MS`, но не для признака «приложение».

## Solution

- `shellLines`: деление на строки с учётом кавычек и `\` перед переводом строки; `#` в начале слова вне кавычек снимается до конца своей строки. Каждая строка разбирается `shell-quote`.
- `shellScript`: для `sh`/`bash`/`ash`/`dash` пропускаются опции до `/^-[A-Za-z]*c[A-Za-z]*$/` (и `-o <имя>`); следующий токен — скрипт.
- `stageCommand`: exec-форма `ENTRYPOINT` без файла входа получает `CMD` аргументами (shell-форма — `/bin/sh -c "<CMD>"`). Если в `ENTRYPOINT` есть `node`, проверяется склейка, иначе — команды `CMD`. Shell-форма `ENTRYPOINT` игнорирует `CMD`. Невалидный JSON — shell-форма (`execForm`).
- `baseComposeFile`: порядок поиска Compose (`compose.yaml`, `compose.yml`, `docker-compose.yaml`, `docker-compose.yml`). Признак «приложение» — по окружению слитого сервиса.
- `stop_grace_period` — через `expandDefaults`; переменная без умолчания — «значение не определено». `SHUTDOWN_TIMEOUT_MS` вне формата — нарушение, значение в текст не попадает (NFR-4). В `env_file` ` #…` снимается у значений без кавычек.
- CI: префикс Docker Hub снимается перед сравнением.
- `NODE_VALUE_OPTIONS` — из `node --help` 22.23.3 и 24.22.1, с алиасами и `--stack-size`.

Тесты добавлены после правки. Каждый случай перед правкой воспроизведён временным спеком (review 3). Снимки сервисов не изменились.

## Prevention

- Разбор чужого формата строится от его грамматики и документации инструмента, а не от встреченных примеров. Чек-лист: строки и комментарии, опции, формы инструкции, слияние файлов, порядок поиска.
- Наследование от базового файла — одним «слитым сервисом» для всех признаков сразу, а не по одному полю.
- Если значение нельзя разобрать, это нарушение формата, а не молчаливое умолчание.
