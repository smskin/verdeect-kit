# assertRepoConventions: правило команды «на запрет» (PRD v1.11)

**Date:** 2026-11-10 03:00
**Files:** src/testing/launch-command.ts, src/testing/repo-conventions.ts, test/unit/testing/ac-1-8-repo-conventions.spec.ts, README.md, CHANGELOG.md
**Severity:** high

## Problem

Review 5 E1 (KT-08, AC-1.8) нашёл два случая, когда нарушение молча пропускалось:
- неизвестная программа перед `node`: `./docker-entrypoint.sh node dist/main.js`, `/bin/sh /entrypoint.sh node …` (в том числе `command:` compose поверх ENTRYPOINT-скрипта). Это регрессия относительно патча 2026-11-10-01.20;
- `bash --login -c …`, `--rcfile f`, `-O extglob`: `shellScript` не понимал длинные опции и `O`.

## Root Cause

Правило было устроено «на разрешение»: оно проверяло только формы, которые узнало. Всё неузнанное считалось «не запуском приложения» и проходило без находки.

## Solution

Правило перестроено «на запрет»:
- у стадии Dockerfile, которой запускается приложение без своего `command:`, и у `scripts.start` обязателен распознанный запуск; иначе — «не найден запуск приложения: <голова>…»;
- `main.*` в аргументах любой команды, кроме файла входа `node`, — `command-unrecognized`;
- `shellCall` пропускает длинные опции (у `--rcfile` и `--init-file` — со значением); `o`/`O` забирают имя опции; если есть `-c`, а скрипт не выделен, — «вызов оболочки не распознан»;
- опции `tini` и `dumb-init` проверяются по списку из README tini и `dumb-init --help`;
- переменная без умолчания — нарушение только на месте программы или обёртки, в опциях `node` до файла входа и в самом файле входа.

Обязательный запуск проверяется и у приложения без `build:` (образ `image:`): для него берутся последние стадии Dockerfile, на которые нет ссылок из `build:`. Этот пропуск найден перед verify, тесты (2) падали до правки. Стадия без CMD и ENTRYPOINT получает текст «не найден запуск приложения: нет CMD и ENTRYPOINT».

Тесты написаны до кода: 15 из 18 падали на прежнем коде, 3 проходили, как и должны были (`node $NODE_FLAGS` уже ловился, два одноразовых задания). Снимки сервисов не изменились. Один прежний тест (CMD `["dist/main.js"]` в отдельной стадии) теперь даёт `command-unrecognized`: это верно по v1.11, потому что такая команда не запускает `node`.

## Prevention

- Правило проверки должно быть «на запрет»: неизвестное — нарушение, а не пропуск.
- После перестройки разбора нужно перепрогонять формы из прежних патчей, чтобы ловить регрессии.
