# internal импортировал значение из /messaging; тест AC-8.6 ловил числа конверта GlitchTip

**Date:** 2026-11-16 12:55
**Files:** src/internal/cleanup-schedule.ts, src/messaging/topology.ts, eslint.config.js, test/integration/redis/ac-8-6-channel-kind.spec.ts, test/package/ac-1-1-package.spec.ts, AGENTS.md
**Severity:** medium

## Problem

1. `/aif-verify --strict` rc.10: `ERROR [architecture]` — `src/internal/cleanup-schedule.ts` импортировал значение `CLEANUP_INTERVAL_MS` из `../messaging/topology.js`. По `ARCHITECTURE.md` `internal` зависит только от `node:*` и `zod`; через этот файл `/idempotency` транзитивно зависел от `/messaging`. `make lint` нарушение не поймал.
2. `make test-full`: `test/integration/redis/ac-8-6-channel-kind.spec.ts` падал детерминированно — `expect(text).not.toContain('42')` по логам и полному телу конверта GlitchTip находил `42` в `lineno`, `timestamp`, `trace_id`, `event_id`. Первый зелёный прогон был случайным.

## Root Cause

1. План (задача 9) предписал импорт константы из `topology.ts`, а сверка с таблицей зависимостей `ARCHITECTURE.md` не проводилась. Блок `no-restricted-imports` для `src/internal/**` перечислял только `@nestjs/*`, `config`, `testing`, `cli` — значения подпутей (`messaging`, `database`, …) не запрещались, поэтому линтер молчал.
2. Проверка «подстроки идентификатора нет» была слишком широкой: короткая подстрока (`42`) по всему тексту конверта, где есть случайные hex-идентификаторы и числа. Тест проверял не то поле, где могло бы появиться имя канала.

## Solution

1. `CLEANUP_INTERVAL_MS` объявлена в `src/internal/cleanup-schedule.ts`; `src/messaging/topology.ts` её реэкспортирует (`messaging → internal` разрешено, снимок констант `topology.spec.ts` не изменился). В `eslint.config.js` для `src/internal/**` добавлен запрет значений `../observability/*`, `../http/*`, `../database/*`, `../idempotency/*`, `../messaging/*`, `../crypto/*`, `../redis/*` (`allowTypeImports: true` — `tx-context.ts` берёт тип `DbContext`). Регрессия: `eslint src/internal` до правки — ошибка на `cleanup-schedule.ts:4`, после — чисто. В `ac-1-1-package.spec.ts` — граф `dist/idempotency` без файлов `messaging/`.
2. AC-8.6 проверяет отсутствие частей имени канала (`t-1:42`, `kind:t-1`) в JSON логов и в полях `exception`/`message` элементов конверта (`eventFields`), плюс контроль, что событие содержит текст ошибки обработчика. На `src/redis/channels.ts` из rc.9 (`de29a13`) тест падает на `not.toContain('t-1:42')` в логах; на rc.10 — зелёный (3 прогона подряд).
3. `AGENTS.md`: в карте `src/internal/` — `cleanup-schedule.ts`, в `src/testing/` — `background-loops`, `delivery`.

## Prevention

- Новый файл в `src/internal/` — сверить импорты с таблицей `ARCHITECTURE.md`; общую константу двух подпутей объявлять в `internal` и реэкспортировать из подпути.
- Lint-границы подпутей должны перечислять все запрещённые подпути явно, а не только «опасные» пакеты.
- Отсутствие идентификатора проверять по полной части имени (`t-1:42`, `kind:t-1`) и только в полях, где он мог бы оказаться (`exception`, `message`, поля логов), не по всему конверту с числами и hex.
- Тест с проверкой «не содержит» прогнать несколько раз: случайные данные дают ложный зелёный.
