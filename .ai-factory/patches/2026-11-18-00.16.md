# Страховка ошибки окружения уровня корня сверяла текст со всем process.env

**Date:** 2026-11-18 00:16
**Files:** src/config/parse-env.ts, src/http/pagination.ts, src/messaging/rabbit-connection.ts, test/unit/config/ac-1-3-parse-env.spec.ts, README.md, CHANGELOG.md
**Severity:** low

## Problem

Review rc.12 (KT-136). У ошибки без пути (`(root)`) `parseEnv` сравнивал `message` со всеми строковыми значениями
переданного `env`. При разборе `process.env` безобидный текст `superRefine` корня «MAIL_DSN обязателен в production»
заменялся на «неверное значение (custom)», потому что `NODE_ENV=production` (фрагмент `producti`). Оператор терял
полезное сообщение без какой-либо утечки. Попутно: в `afterCursor` стоял недостижимый запасной вид `?? 'string'`,
а комментарии `rabbit-connection.ts` описывали фатальный путь только как «406 TTL .retry».

## Root Cause

Решение R2 плана rc.12 («для `(root)` — все строковые значения env») расширило область сверки за пределы того, что
видит проверка корня: `superRefine` получает только разобранные ключи схемы, а не весь процесс. Переменные процесса
вне схемы (`NODE_ENV`, `LANG`, `SHELL`, `PATH`) дают ложные совпадения с обычными словами. `?? 'string'` появился из-за
двух параллельных массивов (`cols`, `kinds`) и `noUncheckedIndexedAccess`.

## Solution

- `rootValues(schema, env)` — значения ключей `shape` схемы (у схемы без `shape` — по-прежнему всё окружение, безопасный
  вариант); ошибка с путём сверяется со значением своего ключа верхнего уровня, как раньше.
- `afterCursor` — один проход по парам `{col, kind}` (`cursorKeys`): проверка значения и параметр с приведением
  строятся в одном `map`, нет вида — `Error` при построении пар; запасной вид убран, поведение не изменилось.
- Комментарии `rabbit-connection.ts` — «MessagingStartupError: 406 своих очередей (TTL .retry, другие аргументы)».
- README и CHANGELOG — область сверки у ошибки корня и правило «значения в текст корня не вставлять».
- Логирования нет: `parseEnv` и `afterCursor` — чистые функции, `console.*` в `src/**` запрещён (AC-9.4).

Регрессионный тест `AC-1.3: ошибка уровня корня — сверка только со значениями ключей схемы…` до правки падал
(«неверное значение (custom)» вместо текста схемы), после — проходит; значение ключа схемы в тексте корня по-прежнему
заменяется.

## Prevention

- Область сверки на утечку значения — та же, что видит код, порождающий текст: для проверки корня это ключи схемы, а не
  всё окружение процесса.
- В тестах страховки моделировать реальный `process.env` с посторонними переменными (`NODE_ENV=production`), а не только
  ключи схемы.
- Параллельные массивы с `?? <умолчание>` ради `noUncheckedIndexedAccess` заменять массивом пар — запасное значение
  иначе маскирует нарушение инварианта.
