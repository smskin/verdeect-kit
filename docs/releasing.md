# Выпуск версии

[← README](../README.md)

Документ для мейнтейнеров. Пакет публикует только CI по защищённому тегу через npm Trusted Publishing; ручная публикация с машины разработчика — не способ выпуска. Единственное исключение — первый выпуск `1.0.0-rc.1` (G13, NFR-6). Конвейер — `.github/workflows/ci.yml`, команды — цели `Makefile`.

## Порядок выпусков (G14)

- **Этапы E1–E8 версий не выпускают.** Изменения копятся в `## [Unreleased]` CHANGELOG; проверка каждого этапа — проект-потребитель на упакованном архиве (AC-9.1). `version` в `package.json` — `1.0.0-rc.1`, номер следующего выпуска; до тега он не публикуется.
- **После E8 — `1.0.0-rc.1`:** вручную мейнтейнером с меткой npm `next`, затем `npm trust` и запрет публикации токенами (раздел «Первый выпуск» ниже).
- **Дальше `1.0.0-rc.N`** — тегом `v1.0.0-rc.N` через CI, метка `next`. На `rc` переходят готовые сервисы (prd.md §10: BFF → Platform → Orchestrator → Identity). Ломающие правки между `rc` допустимы без мажора: перешедшие сервисы обновляют точный пин до следующего `rc` в своих планах.
- **`1.0.0`** — после перехода последнего сервиса (Identity), тегом `v1.0.0` через CI, метка `latest`. С неё действуют правила semver ниже.

## Выпуск по шагам

1. **Проверки локально** (для I, T и `pack:check` нужен Docker):

   ```bash
   make install
   make test-full   # lint, analyse, test, test-integration, test-timing (на тихой машине), pack-check
   ```

   И зелёный CI на `main`.

2. **`version`** в `package.json` — номер выпуска: `1.0.0-rc.N` до перехода Identity, затем `1.0.0` и далее по semver ниже (G14).
3. **Раздел версии в `CHANGELOG.md`**: перенести пункты из `## [Unreleased]` в `## [X.Y.Z] - ГГГГ-ММ-ДД` (или `## [1.0.0-rc.N] - ГГГГ-ММ-ДД`) с датой тега. После `1.0.0` у мажора — подраздел `### Как перейти`. Новый экспорт — строка в `### Added` и в разделе «API» README.
4. **Коммит и тег:**

   ```bash
   git commit -am "chore(release): vX.Y.Z"
   git tag vX.Y.Z
   git push origin main
   git push origin vX.Y.Z
   ```

5. **CI** (`.github/workflows/ci.yml`): lint и test (Node 22 и 24: U + I) → timing и package (`make build pack-check`) → publish. Job `publish` запускается только на теге `v*` после зелёных проверок; `scripts/publish.mjs` принимает только `v<major>.<minor>.<patch>` и `v<major>.<minor>.<patch>-rc.<N>`, остальные теги — отказ без публикации.
6. **Проверить публикацию:** `npm view @verdeect/kit@X.Y.Z version` и `npm view @verdeect/kit dist-tags` (`next` — последний `rc`, `latest` — с `1.0.0`).

## Что проверяет publish до публикации

`scripts/publish.mjs` (AC-1.10):

| Проверка                                                    | Если не прошла                                           |
| ----------------------------------------------------------- | -------------------------------------------------------- |
| `GITHUB_REF_NAME` задан                                     | выход 1                                                  |
| суффикс тега — только `-rc.<N>` или его нет                 | выход 1: «суффикс не поддерживается»                     |
| тег соответствует `v<major>.<minor>.<patch>` или `…-rc.<N>` | выход 1                                                  |
| тег равен `v` + `version` из `package.json`                 | выход 1: «тег vX не совпадает с version Y»               |
| `npm view @verdeect/kit@<version>` — версии нет             | выход 1: «версия уже опубликована, перезапись запрещена» |
| `npm view` ответил ошибкой, отличной от E404                | выход 1: без ответа реестра ничего не публикуется        |

Затем `npm publish --access public --tag next` для тега `-rc.<N>` или `npm publish --access public --tag latest` для тега без суффикса. Токенов скрипт не читает.

## Ошибки выпуска

- **Тег не совпадает с `version`.** Ничего не опубликовано. Удалить тег (`git push origin :refs/tags/vX.Y.Z`, `git tag -d vX.Y.Z`), исправить `version` или поставить правильный тег.
- **Версия уже есть в npm.** Ничего не перезаписано: версию в npm нельзя заменить. Повысить `version` (следующий `rc` или следующая версия), дописать CHANGELOG, поставить новый тег.
- **Суффикс тега не `-rc.<N>`** (`-beta.1`, `-rc`, `-rc.0`). Ничего не опубликовано. Удалить тег и поставить `v<x.y.z>-rc.<N>` или тег без суффикса.

## Semver

До `1.0.0` выходят только `1.0.0-rc.N` (NFR-5): ломающие правки между `rc` допустимы. Правила G14 (prd.md §0) действуют с `1.0.0`:

- **Мажор:** удаление или переименование экспорта, смена сигнатуры или смысла существующего экспорта, новая обязательная переменная `envBase`, новое правило `assertRepoConventions` (валит сервис, который раньше проходил), мажорная смена образа в `TEST_IMAGES`, повышение минимума peer-зависимости на мажор, смена драйвера AMQP.
- **Минор:** новый подпуть, новые экспорты и опции с безопасным умолчанием.
- **Патч:** исправления без изменения контракта.

Исправления, в том числе безопасности, — только патчем последнего мажора, без бэкпортов. Поддерживается только последний мажор (NFR-5). У мажора в CHANGELOG обязателен раздел «Как перейти»: что изменилось и что сделать сервису.

## Авторизация в npm: Trusted Publishing

Пакет публикуется через npm Trusted Publishing (OIDC): job `publish` получает от GitHub короткоживущий `id-token` и обменивает его в npm на токен публикации; provenance npm создаёт автоматически. `NODE_AUTH_TOKEN`, секретов npm и долгоживущих токенов нет нигде (NFR-6).

### Разовая настройка GitHub

| Что                | Где                         | Значение                                                       |
| ------------------ | --------------------------- | -------------------------------------------------------------- |
| environment `npm`  | Settings → Environments     | правило развёртывания: только теги `v*`                        |
| ruleset тегов `v*` | Settings → Rules → Rulesets | создание — только мейнтейнеры; удаление и перезапись запрещены |

### Первый выпуск (1.0.0-rc.1) — вручную мейнтейнером после E8

Trusted Publisher настраивается только для пакета, который уже есть в npm, поэтому `1.0.0-rc.1` мейнтейнер публикует вручную после E8, с 2FA и без токенов, с меткой `next`. У `1.0.0-rc.1` нет provenance — это единственная ручная публикация.

1. Шаги 1–3 выше: проверки зелёные, `version` = `1.0.0-rc.1`, раздел `[1.0.0-rc.1]` в CHANGELOG с датой тега.
2. Поставить тег локально, пока не пушить: `git tag v1.0.0-rc.1`.
3. Чистый клон этого тега, проверки и публикация:

   ```bash
   git clone --branch v1.0.0-rc.1 "$(pwd)" ../verdeect-kit-release
   cd ../verdeect-kit-release
   pnpm install --frozen-lockfile
   pnpm pack:check
   npm login
   npm publish --access public --tag next
   ```

   `npm login` открывает вход в браузере с 2FA и сохраняет короткоживущий сессионный токен. Метка `next` обязательна: без неё npm поставит предварительной версии `latest`.

4. Проверить `npm view @verdeect/kit@1.0.0-rc.1 version` и `npm view @verdeect/kit dist-tags`, затем `npm logout`.
5. Запушить тег: `git push origin v1.0.0-rc.1`. Job `publish` для него упадёт на «версия 1.0.0-rc.1 уже опубликована» — это ожидаемо.

### После первого выпуска — переход на OIDC

1. Связать пакет с workflow:

   ```bash
   npm trust github @verdeect/kit --repo smskin/verdeect-kit --file ci.yml --env npm --allow-publish
   ```

   Имена флагов сверьте с `npm trust github --help`. То же — на странице пакета: Settings → Trusted Publisher.

2. Запретить публикацию токенами: страница пакета → Settings → Publishing access → «Require two-factor authentication and disallow tokens».
3. Удалить клон `../verdeect-kit-release`.
4. Следующие `1.0.0-rc.N` выпускаются только тегом через CI (метка `next`); `1.0.0` — после перехода Identity, тегом `v1.0.0` (метка `latest`). В логе будет «[publish] авторизация: OIDC (Trusted Publishing)».

## Где смотреть логи публикации

Actions → запуск для тега → job `publish`. Строки с префиксом `[publish]`: тег, метка npm, `version`, результат `npm view`, решение, способ авторизации и команда `npm publish`. Причина падения — последняя строка `[publish]` в stderr.
